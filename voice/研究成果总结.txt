========================================================================
 银河天使2 绝对领域之门 (PS2) —— 战斗语音字幕补丁 研究成果总结
 (适用于给同类游戏做类似功能时参考)
========================================================================

一、文件与工具链
------------------------------------------------------------------------
主程序   : SLPM_662.43 (ELF, .text vaddr 0x100000 ↔ 文件偏移 0x1000,
           armips 的 .open 第三参数 headersize = 0xFF000)
汇编器   : armips v0.11 (.ps2 模式)
补丁源码 : patch.asm  → 打补丁.bat → out\SLPM_662.43
调试版本 : patch_debug2~5.asm (内存标记诊断法, 见第五节)
相关文件 :
  slg/voicetbl/slgvNNNNNN.tbl        每关语音表(文本格式, CP932, CRLF)
  slg/stage/NNNN00/stage_soundfile.tbl  关卡→slgv文件映射 ([VOICE]节)
  voice/slgvoice.msh + .msb          语音库 (SCEE MultiStream, PSX ADPCM)
  slg/stage/NNNN00/slg_opdemo.dat    开场小剧场剧本(带文本的那种)

二、tbl 语音表格式 (slgvNNNNNN.tbl)
------------------------------------------------------------------------
[HEAD]  TBLS=7, #NNN = TBL组号 + 注释(舰船名):
        TBL00=ルクシオール(母舰/桥员) TBL01~05=五台纹章机 TBL15=小剧场
[TBLxx_yy]  xx=舰船组号, yy=情境编号, 节内:
        PRIORITY =优先级
        NUM      =条目数
        #000~#NUM-1 =数字行, 7个字段(逗号分隔):
            1.テンション 状态档位0/1/2(按驾驶员状态筛选候选)
            2.フラグ     标志(bit1=强制选用 bit2=启用 bit3=跳过)
            3.キャラID   说话人(开场剧本查人名也用它)
            4.フェイスID 立绘 → [FACEFILES]映射到 adv/face/facXXX.agi
            5.フィルタID 变声滤镜 0=无 2/3=无线电
            6.確率       随机权重 (0=按顺序, 小剧场用)
            7.ボイスID   语音编号 = MSH库里的第N个非空条目(vgmstream同)
        ★第 i 条的台词行 = #(NUM+i) =<文本>   ← 官方预留字段, 游戏解析后
          存到条目+28 (32字节条目: +0语音ID +4角色 +8立绘 +12滤镜u8
          +13权重u8 +14状态u8 +15标志u8 +20使用计数 +24立绘数据 +28台词)
          游戏从不显示它(显示回调从未安装), 我们借来放字幕
        ★TBL15_41~47(小剧场)不加台词: 小剧场语音同样流经我们的hook,
          剧本带文本的会显示两遍; 只有"纯语音无文本"的小剧场才加
关卡映射: stage_soundfile.tbl 的 [VOICE] 节 #NNN =slg/voicetbl/slgvNNNNNN.tbl
          一场战斗只加载一个(或一组)slgv文件

三、语音库 MSH+MSB (SCEE MultiStream)
------------------------------------------------------------------------
MSH(头): 0x00=u32文件长度 0x08=u32条目数 0x0C起每条0x10字节:
          +0 流字节数 +4 config(低字节疑似序号,bit0循环) +8 MSB内偏移
          +12 采样率(本作22050/32000)
          大小或采样率为0=空条目, 不占编号
MSB(数据): PSX SPU ADPCM, 单声道, 16字节/块×28采样
编号: 第N个非空条目 = N = tbl里的ボイスID (vgmstream 的 subsong 同)

四、文本引擎 (补丁显示通道)
------------------------------------------------------------------------
解析:   sub_1CE0A0(缓冲, 串, 最大字数, 速度, 颜色, 速度数组)
        SJIS双字节按引导字节(0x81-0x9F/0xE0-0xFC)处理
        控制码(可直接用在我们的台词里!):
          \sNN 速度  \vN 速度  \cHHHHHH 颜色   0x0A 裸字节=换行
显示:   sub_1CE6F0(文本框对象, 串, 速度18, 颜色, ...) 解析进文本框
        文本框对象7204字节: +4096字形缓冲(512字×8字节) +6144每字速度
        +7172阶段(0打字/1全显/2淡出) +7176字数 +7180已显示数
每帧:   sub_1CE408(文本框, dt) 打字机推进; sub_1CE890 渐显alpha
★战斗场景自带常驻文本框 (本补丁的显示通道):
        战斗场景单例 dword_2CCA6C (sub_15C640 构造时写入)
        对象 = [场景+0x828], 其 +356 = 文本框指针
        对象+360 = 激活开关(0关/1开, sub_16CC18/sub_16CC28 切换)
        对象+372 ≠0 时绘制选项光标条(我们清零=无光标)
        sub_16CC78(对象, 文本) = 塞文本(游戏原生用法, 见sub_164C90/
        sub_1BE288两处调用); 每帧处理器 sub_16C6D8 驱动打字机+淡出
        原生行为: 文字显示后一直保留直到被替换 → 收尾用 sub_16CC28

五、补丁本体 (patch.asm)
------------------------------------------------------------------------
挂钩点: 0x1694B0  (sub_169388 case3 的 jal sub_1262E8, 延迟槽不动)
        此刻 a1=语音ID s6=语音表条目指针(条目+28=台词)
代码洞: 0x1127A8 起 ~0x380字节 (sub_1127A8等死代码, 全程序零引用)
hook流程: 原样播语音 → 读条目+28(无台词则跳过) → 取[2CCA6C]+0x828对象
        → +360写1(激活) +372写0(去光标) → jal sub_16CC78(对象,台词)
应急标记: 0x112960 [0]走到显示次数 [4]hook次数 [8]台词命中次数
底层语音: sub_1262E8(库, ID, 音量0~0x3FFF, 声像, 标志) → ADPCM播放
战斗语音链: sub_164818→sub_1691D8→sub_168038(按权重随机选条目)→
        sub_168ED8(3槽优先队列)→sub_169388(每帧出队播放=hook点)

六、踩过的坑 (重要!)
------------------------------------------------------------------------
1. armips .ps2 不支持 li 宏, 不认 a4~a7 寄存器名(必须写t0~t3)
2. lui+offset 寻址: 低位>=0x8000会符号扩展! 0x2CCA6C 必须
   lui 0x2D + lw -0x3594, 直接 lui 0x2C + lw 0xCA6C 会差0x10000
3. bat 文件中文必须 GBK 编码(cmd按ANSI解析), 汇编源码UTF-8需
   /codepage:65001 (csc同理)
4. 代码洞空间必须核对 -temp 清单: 我们的代码两次溢出覆盖了自己
   的数据区(debug2/初版v5), 教训: .org 固定地址的数据区要放在
   确认小于代码终点之后, 并且看清单里的最终地址
5. MIPS调用约定(本作编译器): a0~a3传参+浮点用$f12/$f13, 但第5~8个
   参数走 $a4~$a7(即t0~t3!), 第11/12参数在调用者 sp+0x10/sp+0x18
   ——是从反汇编调用点逐条核对的, 反编译器的参数标注不可信
6. t寄存器跨jal调用不保留; s6等s寄存器由被调函数保护(hook借用s6
   拿条目指针)

七、方法论(换游戏也适用)
------------------------------------------------------------------------
1. 静态: 从字符串常量(PRIORITY/VOICE/FACEFILES)和调用图定位解析器
2. 读引擎找官方预留的废功能(本作: 条目+28台词字段+从未安装的显示
   回调) —— 比自己造显示管道便宜得多
3. 显示通道优先抄游戏原生用法: 找到现有调用点(sub_164C90/
   sub_1BE288怎么调), 连参数带激活开关一起抄
4. 动态诊断用"内存标记法": 代码洞里放标记块, hook各阶段写阶段码
   和关键指针, 打完一仗读内存 —— 一次测试定位一层, 别靠猜
5. 懒加载单例的get-or-create模式: 游戏自己"取不到就建"的地方
   (本作sub_1F9C90), 补丁照抄同款逻辑
6. 改动前先字节级验证: 汇编后用-temp清单+读回二进制比对差异区间

八、待定事项 → 已全部实现(v6)
------------------------------------------------------------------------
1. 换行: tbl里写\n, hook翻译成0x0A (代码洞0x112980缓冲区128字节)
2. 框的生死同步: 挂钩2在 0x169644 (case4语音播完处, 原为死回调
   jal sub_169B68, 其a7参数=条目+28台词) → 语音结束收框
3. 每帧看门狗: 挂钩3在 0x169388 (队列每帧入口) → 框开着但语音库
   4通道全空闲(被顶掉/掐断的语音) → 立刻收框, 兜住一切泄漏
4. 3D模式门: 头像显示函数sub_19F1C8开头查 场景+1096 的模式值
   (0/1=普通2D显示头像 2=3D战特殊 3/4/5=不显示) → 主hook同规则,
   模式>=2不放字幕, 真正与头像同步
5. 测试开关: 主hook里"无台词跳过"的j指令在 vaddr 0x1127E4
   (文件偏移0x137E4). 正常版=j 0x1128B4; 测试版改nop → 无台词
   语音显示固定文字テスト字幕(0x112B10). 打补丁.bat=正常,
   打补丁_测试.bat=测试, 改开关.py 可手动切
6. 台词颜色码\cHHHHHH 可用, 速度码\sNN可用(解析器原生支持)

九、原生头像/字幕回调系统(重要发现)
------------------------------------------------------------------------
战斗初始化时把 sub_164C90 装入语音管理器+328槽(sub_1699F8安装,
0x15D890处调用) → 每次语音开始(state0)/结束(state2/3)自动触发:
  state0: sub_19F1C8显示头像(内部查模式) + sub_16CC78显示entry+28
          台词 + sub_16CB08显示名字 —— 原生字幕通道!但框的+360激活
          标志在普通战斗中无人置1(唯一激活途径sub_1BE170剧本命令
          实测从不触发) → 原生字幕永远不显示, 我们的补丁补的就是
          这临门一脚的激活
  state2/3: sub_19F468隐藏头像 + sub_16CB90收框(受场景+1780门控)
